# Мобильное приложение для аренды спортивного инвентаря

Кроссплатформенное приложение на **Flutter** для поиска, бронирования и управления арендой спортивного инвентаря.  
Проект разработан в рамках выпускной квалификационной работы (ТУСУР, направление «Программная инженерия», 2025).

> Статус: **учебный прототип / MVP**. Часть функций реализована в демонстрационном виде и требует доработки для production-использования.

## О проекте

Приложение решает задачу организации аренды спортивного инвентаря в едином сервисе: пользователи могут находить нужное оборудование, бронировать его на выбранный период, а владельцы — управлять своим инвентарём и заявками. В рамках ВКР также спроектирована многоролевая модель доступа и административные сценарии управления платформой.

**Ключевые идеи проекта:**
- единая кроссплатформенная кодовая база (Flutter);
- облачная backend-инфраструктура на Firebase;
- работа с данными в реальном времени (Cloud Firestore);
- разделение ролей и сценариев использования (клиент / владелец / администратор);
- ориентация на удобный пользовательский сценарий аренды.

## Основные возможности

### Для клиента (арендатора)
- Регистрация и авторизация.
- Просмотр каталога спортивного инвентаря.
- Поиск и фильтрация оборудования (в т.ч. по параметрам и доступности).
- Просмотр карточки инвентаря с деталями и отзывами.
- Оформление бронирования на выбранный период.
- Просмотр статуса бронирования и истории аренд.
- Управление профилем и пользовательскими данными.
- Взаимодействие с владельцем/сервисом через чат (в рамках реализованных сценариев).

### Для владельца инвентаря
- Управление собственным списком оборудования (добавление, редактирование, просмотр).
- Просмотр и обработка заявок/активных бронирований.
- Контроль доступности инвентаря.
- Профиль владельца и базовые сведения/статистика (в интерфейсе предусмотрены соответствующие экраны и сценарии).

### Для администратора (в рамках ВКР)
- Управление пользователями.
- Управление каталогом инвентаря.
- Управление бронированиями.
- Модерационные и контрольные сценарии платформы.

> Примечание: набор и полнота реализации сценариев могут отличаться в текущей версии репозитория, так как проект является учебным прототипом.

## Технологический стек

### Мобильное приложение
- **Flutter / Dart** (`sdk: ^3.7.2`)
- **flutter_riverpod** — управление состоянием
- **go_router** — навигация/маршрутизация
- **flutter_screenutil** — адаптивная вёрстка
- **cached_network_image**, **image_picker** — работа с изображениями
- **intl**, **timeago**, **flutter_localizations** — локализация и форматирование дат

### Backend и сервисы
- **Firebase Core / Auth** — инициализация и аутентификация
- **Cloud Firestore** — хранение и синхронизация данных
- **Firebase Storage** — хранение файлов/изображений
- **Firebase Messaging** — push-уведомления (зависимость подключена)
- **Firebase Analytics** — аналитика (зависимость подключена)

### Геолокация и карты
- **google_maps_flutter**
- **geolocator**
- **geocoding**
- **flutter_polyline_points**
- **google_places_flutter / flutter_google_places_sdk**

### Прочее
- **shared_preferences** — локальные настройки/кэш пользовательских предпочтений
- **http**, **url_launcher**, **uuid_v4**

## Архитектура и модель данных (кратко)

- Клиентское приложение на Flutter взаимодействует с облачными сервисами Firebase.
- Для хранения данных используется **Cloud Firestore**; в рамках ВКР спроектирована физическая модель данных, ориентированная на эффективные сценарии чтения и работу с документной БД.
- Предусмотрена ролевая модель пользователей (клиент, владелец, администратор) и разграничение доступа на уровне бизнес-логики/правил.
- В структуре проекта заложены ключевые доменные сущности: пользователи, инвентарь, бронирования, отзывы, чаты/сообщения, локации и др.

## Структура проекта

```text
lib/
  core/                 # Конфигурация, маршруты, тема, общие виджеты/экраны
  data/
    models/             # Модели данных (equipment, booking, user, chat, review и др.)
    providers/          # Провайдеры состояния/доступа к данным (Riverpod)
    services/           # Сервисы Firebase, кэша, локации, хранилища и т.д.
  features/
    auth/               # Авторизация, регистрация, восстановление пароля
    booking/            # Бронирование, статусы, списки бронирований
    equipment/          # Каталог/карточка инвентаря, отзывы, фильтры, поиск
    home/               # Домашние экраны (клиент/владелец)
    owner/              # Сценарии владельца (управление инвентарём, бронирования, профиль)
    profile/            # Профиль пользователя, настройки, документы, способы оплаты
    rental_history/     # История аренд и детали
    settings/           # Настройки приложения (в т.ч. кэш)
  utils/                # Вспомогательные утилиты, тестовые/seed-данные
  firebase_options.dart # Сгенерированная конфигурация Firebase
android/ web/ windows/ linux/  # Платформенные проекты
test/                   # Тесты
docs/
  images/
    screenshots/        # Скриншоты интерфейса (из материалов ВКР)
    diagrams/           # Диаграммы и материалы проектирования (из ВКР)
```

> В репозитории также могут присутствовать дополнительные прототипные файлы/заготовки, отражающие учебный характер проекта.

## Начало работы

### Предварительные требования
- [Flutter SDK](https://docs.flutter.dev/get-started/install) (совместимый с Dart `^3.7.2`)
- Установленные инструменты для целевой платформы (Android Studio / Xcode / Chrome / Visual Studio — в зависимости от платформы)
- Аккаунт Firebase и настроенный проект (для полноценного запуска с собственным backend)

### Установка
```bash
git clone https://github.com/zooging/sport_equipment.git
cd sport_equipment
flutter pub get
```

### Настройка Firebase

В репозитории могут присутствовать файлы конфигурации Firebase (`lib/firebase_options.dart`, `android/app/google-services.json`, `firebase.json`). Для запуска на **собственном** Firebase-проекте рекомендуется перенастроить конфигурацию:

1. Создайте проект в [Firebase Console](https://console.firebase.google.com/).
2. Подключите приложения нужных платформ (Android/iOS/Web/Windows).
3. Включите используемые сервисы (как минимум Authentication и Cloud Firestore; при необходимости — Storage, Messaging, Analytics).
4. Сгенерируйте конфигурацию заново:
   ```bash
   dart pub global activate flutterfire_cli
   flutterfire configure
   ```
5. Проверьте правила безопасности Firestore/Storage и настройки индексов под вашу схему данных.

> Если используете существующую конфигурацию, убедитесь, что у вас есть доступ к соответствующему Firebase-проекту и его сервисам.

### Запуск
```bash
flutter run
```

Примеры запуска на конкретных платформах:
```bash
flutter run -d chrome
flutter run -d windows
flutter run -d android
```
